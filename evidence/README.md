# evidence/

Generated by `python tests/run.py --evidence`, and committed on purpose.

Running tests is not the deliverable; being able to show **what was proven** is.
These files are written for someone who has not read the code.

| File | What it answers |
|---|---|
| `results.md` | Every check, the specification identifiers it proves, pass or fail |
| `traceability.md` | For each documented requirement, which test file proves it — and which have none yet |
| `reconciliation.md` | The closing ledger reconciliation from the integration run |
| `run.txt` | The raw captured output, with Python version, platform and timestamp |
| `screenshots/test-run.png` | A rendering of `run.txt` — a picture of a real run, not the proof itself |

**Where to start:** `traceability.md`. It is the only one that answers a
question like *"what proves the platform cannot be a lender?"* without reading
any code.

## Honest state of this directory

The traceability gate is in **report-only** mode until task T24. It currently
reports a large uncovered list, and that list is not a defect — it is
`docs/04-tasks.md` in a second form, and it shrinks as the tasks close. The
gate exists from the first commit precisely so the gap is visible rather than
discovered at the end.

`reconciliation.md` says it has nothing to report rather than printing a
reassuring zero: the ledger (T07, T08) and the integration run (T23) are not
built yet. A zero that nothing computed is worse than an empty report, because
it is believed.

Regenerate this directory in the same commit as any change to `src/`, `tests/`
or `docs/`. Stale evidence is worse than none.
